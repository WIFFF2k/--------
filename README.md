# 灵敢足迹地图查看器

这是一个用于检查原始足迹点是否齐全的本地地图查看器。页面直接读取 `原始数据/灵敢足迹(2023.05.10-2026.11.07).csv`，使用 `wgsLatitude` 和 `wgsLongitude` 在 天地图 底图上绘制全部点位。

## 启动

双击本目录中的 `启动地图.bat` 即可启动，黑色窗口需要保持打开。也可以在本目录运行：

```powershell
./启动地图.ps1
```

脚本会启动本地 HTTP 服务并打开浏览器。页面不能直接双击打开，因为浏览器会限制本地文件读取 CSV。

## 页面功能

- “导出 CSV”按点击时的勾选状态下载新文件，包含当前所有可见记录，不受地图视野限制；未勾选项目对应的记录被移除，重叠项目沿用地图显示规则
- 导出直接复制本次加载的 CSV 原始字节，仅删除隐藏记录所在整行；保留表头、全部列及列顺序、原始行序、重复记录、空值、数值精度、编码标记和原始换行。全部显示时导出文件内容与原始文件完全相同
- 新文件名含“筛选后”、记录数与 UTC 时间，由浏览器下载至下载目录或提示选择位置，不写入或覆盖原始数据。导出期间改变勾选不影响已开始的文件；状态提示中的条数以点击时为准

导出已在真实 Chrome 中点击按钮并保存下载文件验证：默认筛选导出 321,993 条、32,526,047 字节；全部显示导出 324,280 条、32,760,380 字节，SHA-256 与原始文件完全一致；仅隐藏孤立点导出 324,266 条。三个文件均与按原始行筛选得到的字节逐一比对一致，导出中立即切换全部显示仍按点击时的状态生成文件。整个过程仅请求原始 CSV 一次，原文件哈希和相机参数未变；加载期间按钮禁用、完成后恢复可用，页面脚本异常 0 次
- 隐藏项目上方提供“全部显示”“全部隐藏”：统一勾选或取消勾选七个项目，只刷新一次点图层，保持当前相机视角；数据加载完成后才可点击
- “全部显示”恢复全部 324,280 条记录；“全部隐藏”隐藏已列出的飞行及孤立异常项目，仍保留 321,993 条其他足迹，之后可继续单独切换任一项目

快捷按钮已通过真实 Chrome 验证：加载期间禁用、加载后启用，支持混合勾选状态、重复点击和键盘 Enter/空格操作；批量切换与单项操作后的点位逐行符合原始记录，统计同步，相机参数不变。1100×800 窗口下两按钮等宽等高且无横向溢出；刷新仍默认隐藏已列项目，页面脚本异常 0 次

- 逐条读取 CSV，不抽样、不去重
- Web Worker 解析数据，避免解析时阻塞页面
- WebGL 点图层显示全部点位，缩放后可查看密集区域
- 显示总点数、当前加载点数、时间范围和坐标范围
- 点击点位查看时间、坐标、海拔、速度和原始行号

地图底图使用天地图服务，访问地址为 `http://localhost:8765/`。点位数据只在本机浏览器中读取，不会上传。

首次打开地图时相机默认居中中国；“定位全部点”会切换到当前显示数据的完整范围，包含需要核查的异常坐标点

## 下载铁路 GPX → 转 CSV → 导入灵敢足迹

适用于灵敢足迹 5.7.4。输入为出发站、到达站、乘车日期；输出为只含这些 GPX 点的一份 CSV，保存到 `D:\Demo\灵敢足迹\GPX`。往返按两条路线分别处理。

### 1. 下载铁路 GPX

1. 打开 [gpx.studio](https://gpx.studio/zh/app#8.28/31.11/104.313)，新建轨迹，选择铁路路线规划模式。
2. 找到出发站、到达站，在铁路轨道上设置起终点。注意南京与南京南等同城不同站，避免把国铁站点吸附到邻近地铁；需要指定途经线路时增加途经点。
3. 沿铁路规划路线后导出 GPX，保存为 `出发站-到达站_YYYY-MM-DD.gpx`。返程另建路线下载，原件与副本只取一份参与转换。

程序下载可使用该网站铁路模式所用的 BRouter `rail` 服务。请求中的坐标为 WGS84，顺序是“经度,纬度”，多个点用 `|` 连接：

```text
https://brouter.de/brouter?lonlats=起点经度,起点纬度|终点经度,终点纬度&profile=rail&format=gpx&alternativeidx=0
```

现有站点坐标和请求实例保存在 `GPX/routes.json`。规划结果是铁路网络路线；有明确车次或经由要求时，使用途经点限定路线。

### 2. 将 GPX 转为 CSV

读取每条 GPX 所有轨迹段的点，保持点顺序，保留 WGS84 坐标及海拔；原 GPX 不改写。多条路线写入同一份 CSV。使用 UTF-8 无 BOM、英文逗号、LF 换行，保留末尾换行，表头及列顺序固定为：

```csv
geoTime,latitude,longitude,wgsLatitude,wgsLongitude,altitude,course,horizontalAccuracy,verticalAccuracy,speed,dayTimeMills,networkType,networkName,locationType
```

| 字段 | 填写方式 |
| --- | --- |
| `geoTime` | Unix 毫秒时间戳，整数，每个点唯一。 |
| `latitude`、`longitude` | GPX 的 WGS84 坐标转换成 GCJ-02 纬度、经度。国内铁路采用 `coordtransform@2.1.2` 的 `wgs84togcj02(经度, 纬度)`，返回值也是经度在前。 |
| `wgsLatitude`、`wgsLongitude` | GPX 原始纬度、经度，保留精度。 |
| `altitude` | GPX 的 `ele`；缺失填 `0`。 |
| `course`、`horizontalAccuracy`、`verticalAccuracy`、`speed` | GPX 未提供时均填 `0`，作为占位值。 |
| `dayTimeMills` | 所属日期北京时间 `00:00:00+08:00` 的 Unix 毫秒时间戳。 |
| `networkType` | 填 `0`。 |
| `networkName` | 留空。 |
| `locationType` | **填 `0`，这是本流程成功显示轨迹点所采用的值。** |

**除 `networkName` 外，不留空数值字段；两组经纬度都要填齐。**

时间安排：有有效实测时间则保留；没有时间或所有时间相同时，按指定日期人工安排，默认北京时间 12:00 起每点递增一秒，同日多条路线依次接续，避开软件现存记录已占用的秒。人工时间需获得用户同意，不代表实际行程时长；当天排不下时另行确定起始时间，不自动跨日。`geoTime` 和 `dayTimeMills` 都使用毫秒，不能写成秒；北京时间 12:00 对应 GPX 的 UTC `04:00:00Z`。

**不能让所有点使用同一个时间戳。** 按 `geoTime` 升序输出为约定的 CSV 文件名；修正时覆盖同一输出文件，不额外生成多个“修正版”。

### 3. 导入灵敢足迹

将生成的 CSV 传到手机，通过灵敢足迹的 CSV 导入功能选择该文件，导入后切换到指定日期查看足迹。

**如果此前导入过错误版本，先备份并删除那批错误的导入记录，再导入正确 CSV。** 相同时间戳重导曾保留旧字段，不能靠修改文件再重复导入来替换它们；删除范围只限这批记录，不删除同日原有足迹。新路线首次导入无需执行删除。

本流程直接使用完整 GPX，不要求每次三点测试或重新导出。核心条件是：**十四列齐全、两组坐标正确、`locationType=0`、时间戳唯一、旧错误记录先处理。** 当前项目网页的 GPX 导出仍存在空字段和相同时间戳，转换时按本节生成 CSV，不直接使用其导出结果。
